# 模块设计（初版）

目的：固定系统静态拆分与职责边界，供概要设计与实现对齐。  
需求对照：`docs/requirements_understanding.md`。术语：`docs/glossary.md`。  
本文只描述**模块**（有什么、谁干什么）。流程/状态机见 `docs/flow_design.md`。

---

## 1. 分层总览

先按 **前端 / 后端** 两大块划分，再拆后端模块。

```text
┌─────────────────────────────────────┐
│ 前端：操作员工作台（同一页面流程）      │
│ 上传/开票 → 核对结果 → 确认/改/作废    │
└─────────────────┬───────────────────┘
                  │
┌─────────────────▼───────────────────┐
│ 后端                                  │
│  接入 │ 解析 │ 校验 │ 主数据          │
│  会话/Agent │ 可观测性                 │
└─────────────────────────────────────┘
```

| 大层 | 包含 | 说明 |
| --- | --- | --- |
| **前端** | 操作员工作台 | 录入与结果确认在同一界面，不拆成「录入模块 + 展示模块」 |
| **后端** | 接入、解析、校验、主数据、会话/Agent、可观测性 | 核心能力与编排 |

---

## 2. 模块清单

| 编号 | 模块 | 所属 | 一句话职责 |
| --- | --- | --- | --- |
| M-FE | 操作员工作台 | 前端 | 操作员完成一票单的上传、核对、修改与确认 |
| M-GW | 接入 | 后端 | 对外 API/MCP 入口、路由与入参校验 |
| M-PAR | 解析 | 后端 | 单据识别、文本规整、字段抽取 → raw |
| M-VAL | 校验 | 后端 | 结构检查 + 业务规则 + 结论汇总（可独立多次调用） |
| M-MD | 主数据 | 后端 | 白名单与阈值等参照数据，以模块函数供校验调用 |
| M-AGT | 会话/Agent | 后端 | 意图、会话状态、调度解析/校验、人工分流 |
| M-OBS | 可观测性 | 后端（横切） | 日志 / 指标 / 链路追踪（本期先日志） |

## 3. 模块职责

### 3.1 M-FE 操作员工作台（前端）

架子模板：`docs/ui_design.md`（以 `docs/ui_mockups/v4/ui_v4_01_idle.jpg` 为准）——顶进度 + 中区随状态 + 底指令/拖文件栏；各状态不换外壳。

| 做 | 不做 |
| --- | --- |
| 上传 PDF、开票 / 结案 / 换票操作 | 不实现抽取与业务规则引擎 |
| 同页展示关键结果与校验结论 | 不单独做「只读展示系统」 |
| 人工改字段、确认提交或作废 | — |
| 底栏文字指令（及拖入 PDF） | — |

与后端：主要对话 **M-AGT**（或经 M-GW 暴露的会话/业务 API）。

---

### 3.2 M-GW 接入（后端）

对外「露出来」的一层，偏 API 路由与协议适配。

| 做 | 不做 |
| --- | --- |
| HTTP 路由（如 `/api/parse_booking`） | 不抽字段、不跑 BR |
| MCP Tool 入口（**优先**，与 HTTP 共用核心逻辑） | — |
| 入参判别：base64 / 路径 | — |
| **是否为合法 PDF**（格式/可打开） | 不判断「是不是托运单」（归解析） |
| 统一错误与响应外壳 | — |

`parse_booking` 对外可一次返回三件套；内部编排为 **解析 → 校验**，校验仍是独立模块。

---

### 3.3 M-PAR 解析（后端）

| 能力点 | 说明 |
| --- | --- |
| 单据类型识别 | 是否为托运/订舱类单证；不是则明确失败，不强行抽字段 |
| 标准化 / 规整 | 清洗文本、统一编码与常见写法（原文「输入验证与标准化」主要落此） |
| 字段抽取 | 默认 LLM；后端可配置切换（Docling/混合等） |
| 产出 | `raw_extracted_data` |

样例 PDF 有文本层：优先文本；抽不出再 OCR/视觉（扫描件为扩展）。

| 做 | 不做 |
| --- | --- |
| 规整 + 抽取 + 类型识别 | 不做装港≠卸港等业务硬规则（归 M-VAL） |

---

### 3.4 M-VAL 校验（后端，独立）

必须可被 **多次调用**（抽完一次；人工/动态改数后再一次）。

| 子能力 | 性质 | 说明 |
| --- | --- | --- |
| 结构 / 格式检查 | 检查 | JSON key、类型、containers 形态等 |
| 业务规则检查 | 检查 | BR-01～06 等 |
| 结论汇总 | 汇总 | PASS/WARN/FAIL、`validation_report` |

| 做 | 不做 |
| --- | --- |
| 产出 `validated_data` + `validation_report` | 不做整段 PDF 文本规整（归 M-PAR） |
| 通过 M-MD 函数查白名单/阈值 | 不管会话状态、不开新单 |

说明：人改字段后再校验，一般不再走 PDF 规整；单位等写法由改数接口或极薄字段规范保证。

---

### 3.5 M-MD 主数据（后端）

参照数据，不是业务单据。

| 数据 | 用途 |
| --- | --- |
| 船名白名单 | BR-03 |
| 港口白名单（名/码） | BR-06 |
| 单位数值阈值 | BR-02 |

以 **模块函数** 对外（非独立 HTTP 管理服务），例如：

- `is_known_vessel(name)`
- `match_port(text)`
- `weight_limits(unit)`

底层先文件/配置；以后可换存储而不改校验逻辑。航次不做白名单。

---

### 3.6 M-AGT 会话 / Agent（后端，独立）

| 做 | 不做 |
| --- | --- |
| 意图识别（开票/改数/提交/换票等） | 意图识别内不直接执行解析 |
| 工具调用节点：按意图调解析或校验 | 不实现 LLM 抽字段细节 |
| 读 `validation_report` 分流（校验网关） | 初抽后不在 Agent 内重跑第二套规则引擎 |
| 单据会话：开始/结束/新单；同时一票 | — |
| 提交策略（`manual` / `auto_on_pass`，默认人工） | 见 AGT-06、flow_design |
| 维护录入容器：`meta`（字段来源）、`history`（过程轨迹） | 见 DATA-01～03；默认来源 llm |
| 人工兜底、改数后再调 M-VAL | — |

意图与工具调用分开：

```text
意图识别（决策 + 参数，如 pdf_ref）
    → 工具调用节点
         ├─ 开票+有 PDF → M-PAR → M-VAL
         ├─ 改数       → 改字段 → M-VAL
         └─ 提交/作废  → 更新会话
```

---

### 3.7 M-OBS 可观测性（横切）

模块名与原文「可观测性」对齐；下含三类能力：

| 子能力 | 本期 | 说明 |
| --- | --- | --- |
| 日志 | **实现** | 耗时、LLM 字段置信度、关键错误（进阶 B） |
| 指标 | 预留 | QPS、失败率、耗时分布等 |
| 链路追踪 | 预留 | 一次请求跨接入→解析→校验→Agent 的定位 |

挂点：优先在接入与核心服务函数上埋点，避免侵入业务规则细节。

## 4. 模块依赖（结构关系）

```text
M-FE
  └──► M-AGT
          ├──► M-GW / 直接编排
          ├──► M-PAR  （开票/重新上传时）
          └──► M-VAL  （抽完后、改数后）

M-GW ──► M-PAR ──► M-VAL
              └──►（类型识别、规整、抽取）

M-VAL ──► M-MD（函数）

M-OBS ──横切──► M-GW / M-PAR / M-VAL / M-AGT
```

| 调用方 | 被调方 | 何时 |
| --- | --- | --- |
| M-FE | M-AGT | 操作员一切动作 |
| M-AGT | M-PAR | 意图为开票且有 PDF |
| M-AGT | M-VAL | 解析后；人工/动态改数后 |
| M-GW | M-PAR、M-VAL | 独立调用 `parse_booking` 时 |
| M-VAL | M-MD | 白名单、阈值 |

## 6. 明确不采用的拆法

| 不采用 | 原因 |
| --- | --- |
| 前端拆「录入模块 + 展示模块」 | 同一工作台页面上的步骤，不是两个模块 |
| 校验嵌死在解析内、不可单调 | 人工改数后无法再验 |
| 标准化放在校验模块 | 已约定归解析 |
| 主数据做成独立对外管理 API（本期） | 模块函数 + 配置即可 |
| 可观测性=仅改名日志且不留扩展 | 保留指标/追踪设计位 |
