# 前端 UI 设计说明（初版）

示意参考：`docs/ui_mockups/v4/`。  
**整站架子以 v4「空闲 Idle」屏为模板**（`ui_v4_01_idle.jpg`）：各状态共用同一外壳，只替换中间内容区。

---

## 1. 页面架子（固定三区）

```text
┌─────────────────────────────────────────┐
│ 顶栏：生命周期进度（固定样式）              │
├─────────────────────────────────────────┤
│ 中区：随会话状态变化（唯一可变主内容）        │
├─────────────────────────────────────────┤
│ 底栏：指令输入 / 拖入 PDF（固定样式）        │
└─────────────────────────────────────────┘
```

| 区域 | 规则 |
| --- | --- |
| **顶栏** | 一条细实线 + 四节点：`空闲` → `处理中` → `待确认` → `完成`；仅高亮当前步，不要多种线型、不要另起状态条 |
| **中区** | 按 Idle / Parsing·Validating / AwaitConfirm / AwaitHuman 换内容；保持留白、信息克制 |
| **底栏** | 与 Idle 模板同一矮输入框：占位「输入指令，或拖入 PDF…」+ 发送；各状态外观一致，可按状态禁用发送/提示，但不换组件形态 |

---

## 2. 状态 × 中区（架子不变）

| 会话状态 | 顶栏高亮 | 中区（示意） |
| --- | --- | --- |
| Idle | 空闲 | 简短提示，引导上传或输入 |
| Parsing / Validating | 处理中 | 加载提示 + 文件名 |
| AwaitConfirm | 待确认 | 少量关键字段 + 提交 / 修改 |
| AwaitHuman | 待确认（FAIL 用中区错误表达，不单开第五步） | 短错误 + 重试 / 作废 |
| 提交成功后 | 完成（可短暂展示）再回空闲 | 成功提示或直接回 Idle 中区 |

---

## 3. 底栏与 Agent

底栏是操作员与 **M-AGT** 的主入口：拖入 PDF、文字指令（改字段、提交、作废等）。  
实现时各状态共用同一 Composer 组件，避免「有的大拖拽区、有的小输入条」。
